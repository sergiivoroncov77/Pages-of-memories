# Где хранить книги, фото, голос и видео: исследование (октябрь 2026)

Цель: чтобы семья могла вести общую книгу с разных телефонов — без сложной регистрации, с фото, голосом и видео, бесплатно на время теста и недорого потом.

Цифры взяты из документации и прайсов поставщиков, актуальных на сентябрь–октябрь 2026 года: из исходников их сайтов на GitHub и из официальных страниц. Пометка **[не проверено]** — факт подтвердить не удалось, его стоит проверить самим.

## Коротко

1. **Сейчас, без сервера.** Книгой делятся файлом: «Книга → Поделиться», затем у близкого «Открыть файл книги». Изменения сливаются, когда файл присылают обратно. Для теста с семьёй этого хватает. Минус: нет живой синхронизации, и удаления на другие устройства не переносятся.
2. **Следующий шаг — облако, но приложение остаётся «локальным».** Книга по-прежнему живёт на телефоне (снимок плюс IndexedDB): так работают фильм и офлайн-режим. Поверх добавляется синхронизация с сервером.
3. **Какой сервер выбрать, зависит от того, где живут близкие:**
   - **за пределами России** — **Supabase Free**. Это база, файлы, анонимный вход и живые обновления в одном SDK. Хорошо работает с нашим статическим сайтом на GitHub Pages.
   - **в России** — сначала проверить, открывается ли Supabase с их телефонов. Он работает через Cloudflare, а Cloudflare с июня 2025 года режут российские провайдеры. Запасной путь: **свой PocketBase на российском VPS** или **Яндекс Облако** (Object Storage, Functions и YDB с бесплатными лимитами; нужна российская карта).
4. **Медиа сжимаются прямо на телефоне перед загрузкой**: фото до ~2048 px, голос Opus 32 кбит/с, видео 720p. Тогда типичная книга занимает около 0,3 ГБ вместо 1,5–2 ГБ и укладывается в бесплатные лимиты.
5. **Ссылки на YouTube, Rutube или VK Видео можно встроить плеером в страницу момента.** В фильм главы они не попадут: браузер запрещает записывать чужой видеопоток в ролик. В фильм идут только файлы, загруженные в приложение.

## «Ссылка вместо загрузки»

Наш фильм рисует кадры на `<canvas>` и записывает его. Если в canvas попадёт чужая картинка или видео без разрешения CORS, браузер запретит запись. Чужое аудио без CORS в WebAudio звучит тишиной. Поэтому:

| Источник | Встроить плеер в момент | Использовать в фильме |
|---|---|---|
| YouTube (по ссылке) | Да | Нет: условия запрещают скачивание, CORS нет. В России фактически заблокирован с февраля 2026 |
| Rutube, VK Видео | Да (iframe) | Нет |
| Vimeo | Да | Только свои видео через API с токеном, не из браузера |
| Google Диск | Да (окно предпросмотра) | Возможно через Drive API для файлов «по ссылке» [CORS не проверено] |
| Google Фото, общие альбомы | Нет | Нет: API общих альбомов закрыт 31.03.2025 |
| Dropbox | Да | Ненадёжно: нет CORS, обходной домен официально не поддерживается |
| Яндекс Диск, публичная ссылка | [не проверено] | Публичный API выдаёт ссылку на скачивание [CORS не проверено; вероятно, нужен маленький прокси] |
| SoundCloud | Да | Нет |
| Telegram | Только посты публичных каналов | Нет; в России в 2026 году замедлен или заблокирован |

**Что реально сделать:**
1. Новый тип материала «ссылка» показывает встроенный плеер из разрешённого списка (YouTube, Rutube, VK, Vimeo, SoundCloud, Google Диск).
2. Кнопка «Импортировать» пробует скачать файл. Если удалось, материал становится обычным загруженным файлом и попадает в фильм.
3. В фильме материал-ссылка показывается титром «смотрите в книге».

## Совместный доступ без регистрации

**Секретная ссылка-приглашение.** Вид: `…/Pages-of-memories/#/join/<id книги>.<секрет>`.
- Секрет стоит после `#`, поэтому не уходит на сервер и в логи.
- На сервере хранится только его хеш.
- Ссылки для «читать» и «дописывать» отдельные. Ссылку можно отозвать и выпустить новую.

**Как это выглядит в Supabase:**
1. Приложение выполняет анонимный вход.
2. Функция `redeem_invite` сверяет хеш секрета и добавляет человека в участники книги.
3. Политики RLS на всех таблицах и файлах проверяют членство.
4. Позже анонимного пользователя можно привязать к e-mail или Google (`updateUser` или `linkIdentity`). Его id не меняется, поэтому данные не теряются.

**Риски:**
- Ссылка — это пароль: кому её переслали, у того есть доступ.
- Анонимная сессия живёт в браузере. Если браузер очистить, понадобится заново открыть ссылку и выбрать «это я» в списке близких.
- Файлы держим в приватном бакете и отдаём только участникам.

## Доступность из России (факты на 2025–2026)

- **Cloudflare.** С 09.06.2025 крупные провайдеры режут трафик через Cloudflare примерно до 16 КБ на соединение ([блог Cloudflare](https://blog.cloudflare.com/russian-internet-users-are-unable-to-access-the-open-internet/)). Под это попадают Workers, Pages, R2 и, по нашему выводу, Supabase: он сам пишет, что работает через Cloudflare.
- **YouTube** фактически заблокирован с февраля 2026 года. **Telegram** замедлен или заблокирован весной 2026; что с ним после апреля — [не проверено].
- **GitHub.** С мая 2026 растёт доля сбоев (OONI); работу `*.github.io` из России — [не проверено].
- **Мобильный интернет.** В части регионов действуют «белые списки»: в отключения любой сервер вне списка недоступен по мобильной сети.
- **Оплата.** Российские Visa и Mastercard за рубежом не работают; Supabase и Appwrite принимают только карты. Яндекс Облако принимает «Мир» и СБП.

**Практический совет:** прежде чем писать код синхронизации, откройте с телефонов близких — по мобильной сети и по Wi‑Fi — тестовый адрес Supabase и сайт приложения.

## Сколько места нужно одной книге

| | Как снято | После сжатия в браузере |
|---|---|---|
| 200 фото по 1–2 МБ | 0,2–0,4 ГБ | 0,06–0,12 ГБ |
| 50 голосовых по 1–5 мин | 0,05–0,25 ГБ | 0,01–0,06 ГБ |
| 10–20 видео с телефона | 0,2–4 ГБ | 0,03–0,5 ГБ |
| **Итого** | **обычно 1,5–2 ГБ** | **обычно ~0,3 ГБ** |

- **Supabase Free** вмещает примерно одну сжатую книгу. Видео больше 50 МБ сервер отклонит, поэтому без сжатия не обойтись.
- **R2 и B2** вмещают по 10 ГБ.
- **Яндекс Object Storage** даёт 1 ГБ места, но 100 ГБ трафика в месяц.

**Как сжимать на телефоне:**
- Фото: `createImageBitmap`, затем canvas и `toBlob('image/webp', 0.8)`.
- Голос: тот же MediaRecorder с Opus 24–32 кбит/с.
- Видео: WebCodecs (библиотека Mediabunny) или перезапись через canvas и MediaRecorder. Это медленно, поэтому нужен индикатор прогресса.

## Предлагаемая архитектура (вариант на Supabase)

1. **Таблицы:** `books`, `book_members` (участник, роль, «кто я в книге»), `book_invites` (хеш секрета, роль, срок, отзыв) и общая `entities` (главы, моменты, рассказы, отклики, медиа, люди) в формате JSON с `updated_at`.
2. **Права:** функция `is_member(book, роль)` и политики RLS на таблицах и файлах (путь `<bookId>/<assetId>`).
3. **Синхронизация:**
   - при открытии подтягиваем изменения с прошлого раза;
   - локальные изменения копятся в очереди и отправляются пачками;
   - живые обновления приходят через Realtime;
   - конфликты решаются по более свежей правке — как сейчас при слиянии файла книги.
4. **Медиа:**
   - сжать на телефоне;
   - загрузить с докачкой по протоколу TUS частями по 6 МБ;
   - на другом устройстве скачать и положить в IndexedDB. Тогда фильм и офлайн-режим работают без изменений.
5. **Приглашение:** «Поделиться» создаёт ссылку `#/join/…`. Близкий открывает её, анонимно входит и выбирает себя в списке близких.
6. **Эксплуатация:**
   - ежедневный запрос из GitHub Actions, чтобы бесплатный проект не засыпал;
   - показ занятого места книгой;
   - позже вход через e-mail или Google для владельца.
7. **Рост:**
   - Supabase Pro за $25 в месяц: без засыпания, файлы до 500 ГБ, 100 ГБ места, 250 ГБ трафика;
   - при большом трафике медиа переезжают в R2;
   - для России — Яндекс Object Storage с PocketBase.
